# Work Summary: Value Resolver, Tagged Services, and Key Uniqueness Validation

**Date:** January 15, 2026  
**Branch:** `feat/code/value_resolver__tagged_custom_hydrator__more`

## Overview

This work session implemented several major features for the DataMapperBundle, enhancing the Symfony integration for the DataMapper library. The main deliverables include a new value resolver for controller parameters, support for tagged services, and compile-time validation for key uniqueness.

## Completed Tasks

### 1. HandleObject Attribute and Value Resolver

Created a complete value resolver system for automatic object hydration in controller actions:

- **`HandleObject` Attribute** (`src/Attribute/HandleObject.php`)
  - PHP 8 attribute for controller parameter decoration
  - Supports mapping from multiple request sources
  - Allows storing values in hydration context with `context:` prefix

- **`HandleObjectValueResolver`** (`src/ValueResolver/HandleObjectValueResolver.php`)
  - Implements `ValueResolverInterface`
  - Extracts values from route parameters, query strings, headers, and JSON body
  - Integrates with DataMapper for object hydration
  - Handles optional headers (X- prefix) gracefully

### 2. Tagged Service Support for Custom Hydrators

- **`CustomHydratorPass`** (`src/DependencyInjection/Compiler/CustomHydratorPass.php`)
  - Compiler pass that collects services tagged with `kassko_data_mapper.custom_hydrator`
  - Merges tagged services with semantic configuration
  - Validates key uniqueness at compile time
  - Requires `key` attribute on each tag

### 3. Tagged Service Support for Custom Object Mappers

- **`CustomObjectMapperPass`** (`src/DependencyInjection/Compiler/CustomObjectMapperPass.php`)
  - Similar to hydrator pass, for `kassko_data_mapper.custom_object_mapper` tag
  - Full key uniqueness validation
  - Merges with `custom_object_mappers` configuration

### 4. Key Uniqueness Validation

- **`DuplicateKeyException`** (`src/Exception/DuplicateKeyException.php`)
  - Custom exception thrown when duplicate keys are detected
  - Clear error messages indicating conflicting service IDs

### 5. Configuration Updates

- Added `custom_object_mappers` configuration option
- Updated `KasskoDataMapperExtension` to process the new option
- Updated `DataMapperFactory` to accept and pass object mappers

## Technical Decisions

1. **Final Class Handling**: The DataMapper class is final, so unit tests for the value resolver use real instances instead of mocks.

2. **Optional Headers**: Headers prefixed with `X-` are treated as optional, following common HTTP conventions.

3. **Compile-Time Validation**: Key uniqueness is validated during container compilation, providing early feedback.

4. **No Backward Compatibility Concerns**: As this is a beta version, no deprecated APIs were maintained.
