## Fichiers créés

### 1. Workflow CI pour le bundle (`.github/workflows/ci.yml`)

Workflow d'intégration continue pour le bundle DataMapper Symfony.

**Déclencheurs :**
- Push sur la branche `2.0`
- Pull requests vers la branche `2.0`

**Jobs :**

| Job | Description |
|-----|-------------|
| `tests` | Exécute les tests PHPUnit sur une matrice PHP/Symfony |
| `code-quality` | Vérifie la syntaxe PHP |
| `validate-composer` | Valide le fichier composer.json |

**Matrice de tests :**
- PHP : 8.1, 8.2, 8.3
- Symfony : 5.4.*, 6.4.*, 7.0.*, 7.1.*
- Exclusion : Symfony 7.x avec PHP 8.1 (non supporté)

### 2. Workflow de validation des métadonnées (`resources/github/data_mapper_validation.yml`)

Workflow réutilisable pour les projets utilisant DataMapper.

**Objectif :** Valider les métadonnées des data objects lors des CI/CD des projets clients.

**Commande exécutée :**
```bash
php bin/console datamapper:validate <path> [--namespace=<namespace>] [--fail-on-warning]
```

**Variables de configuration :**

| Variable | Description | Exemple |
|----------|-------------|---------|
| `DATA_OBJECTS_PATH` | Chemin vers les data objects | `src/Entity` |
| `DATA_OBJECTS_NAMESPACE` | Namespace des classes | `App\Entity` |
| `FAIL_ON_WARNING` | Échouer si warnings | `true` / `false` |

**Déclencheurs par défaut :**
- Push sur `main`, `master`, `develop`
- Pull requests vers ces branches

**Usage :**
1. Copier le fichier vers `.github/workflows/data_mapper_validation.yml` dans le projet client
2. Configurer les variables `DATA_OBJECTS_PATH` et `DATA_OBJECTS_NAMESPACE`
3. Optionnellement activer `FAIL_ON_WARNING`

**Note :** Ce workflow sera intégré dans les Symfony Flex recipes à l'avenir.
