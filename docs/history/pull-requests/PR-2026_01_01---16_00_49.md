# Pull Request: Synchronize Bundle with Data-Mapper v2.40.0-alpha

## Summary

This PR updates the `kassko/data-mapper-bundle` Symfony bundle to synchronize with the updated core library `kassko/data-mapper:^2.40.0-alpha`.

## Changes

### Dependency Updates

- **composer.json**: Updated `kassko/data-mapper` dependency from `^2.32` to `^2.40`
- **composer.json**: Added `psr/simple-cache` dependency for cache interface support

### New Configuration Options

Added the following new configuration options to `kassko_data_mapper.yaml`:

- **`enable_cascade_collection`**: Boolean to enable attribute cascade/inheritance event collection (default: `false`)
- **`custom_hydrators`**: Array of custom hydrator service IDs keyed by name
- **`sensitive_keys`**: Array of sensitive key names with their visibility levels (`show`, `mask`, `hide`)
- **`default_sensitive_level`**: Default sensitive level for all properties in data lineage (`show`, `mask`, `hide`)

### New Services

- **`DataMapperFactory`**: New factory service that handles conversion of configuration string values to proper enum types (e.g., `SensitiveLevel` enum)
- **`Hydrator`**: Exposed as a service via factory method on DataMapper (`getHydrator()`)

### Updated Services

- **`DataMapperConfigurator`**: Added `$enableCascadeCollection` parameter for enabling cascade collection during DataMapper configuration
- **`services.yaml`**: Updated DataMapper service to use factory pattern, added Hydrator service and alias

### Documentation

- **README.md**: Updated requirements (v2.40+), added documentation for new configuration options (sensitive data handling, custom hydrators, cascade collection)

## Migration Notes

### Configuration Changes

The following new configuration options can be added to existing configurations:

```yaml
kassko_data_mapper:
    # New options (all have sensible defaults)
    enable_cascade_collection: false
    custom_hydrators: []
    sensitive_keys: []
    default_sensitive_level: 'show'
```

### Sensitive Data Protection

For production environments with lineage collection enabled, consider configuring sensitive keys:

```yaml
kassko_data_mapper:
    enable_lineage_collection: true
    sensitive_keys:
        password: hide
        api_key: hide
        token: mask
        secret: hide
    default_sensitive_level: show
```
