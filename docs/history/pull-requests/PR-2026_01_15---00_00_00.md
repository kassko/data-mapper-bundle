# Pull Request: Value Resolver, Tagged Services, and Key Uniqueness Validation

## Summary

This PR introduces several major features to the DataMapperBundle:

1. **HandleObject Value Resolver** - A new controller parameter attribute for automatic object hydration from request data
2. **Tagged Custom Hydrator Services** - Support for registering custom hydrators via Symfony service tags
3. **Tagged Custom Object Mapper Services** - Support for registering custom object mappers via Symfony service tags
4. **Key Uniqueness Validation** - Compile-time validation to ensure hydrator and object mapper keys are unique

## New Features

### 1. HandleObject Value Resolver

Added a new `#[HandleObject]` attribute for controller action parameters that automatically hydrates objects from HTTP request data using DataMapper.

**Usage Example:**

```php
use Kassko\Bundle\DataMapperBundle\Attribute\HandleObject;

#[Route('/products/{barcode}', name: 'api_products_get', methods: ['GET'])]
public function getProduct(
    #[HandleObject([
        'request:barcode' => 'barcode',
        'header:Tenant-Id' => 'tenantId',
        'header:feature-flags' => 'context:featureFlags',
        'header:x-request-id' => 'context:requestId',
    ])]
    Product $product,
): JsonResponse {
    // $product is automatically hydrated
}
```

**Supported mapping sources:**
- `request:param` - Route parameters
- `query:param` - Query string parameters  
- `header:Name` - HTTP headers (case-insensitive)
- `body:field` - JSON body fields

**Target types:**
- Direct property names for object hydration
- `context:key` prefix to store values in DataMapper hydration context

Headers prefixed with `X-` are treated as optional.

### 2. Tagged Custom Hydrator Services

Custom hydrators can now be registered via Symfony service tags as an alternative to semantic configuration:

```yaml
services:
    App\Hydrator\DateTimeHydrator:
        tags:
            - { name: 'kassko_data_mapper.custom_hydrator', key: 'datetime' }
```

The `key` attribute is required and must be unique across all hydrators.

### 3. Tagged Custom Object Mapper Services

Custom object mappers can also be registered via service tags:

```yaml
services:
    App\ObjectMapper\ProductMapper:
        tags:
            - { name: 'kassko_data_mapper.custom_object_mapper', key: 'product' }
```

### 4. Custom Object Mappers Configuration

Added new configuration option `custom_object_mappers` to complement `custom_hydrators`:

```yaml
kassko_data_mapper:
    custom_object_mappers:
        product: 'app.object_mapper.product'
        order: 'app.object_mapper.order'
```

### 5. Key Uniqueness Validation

The bundle now validates at compile-time that:
- No two tagged hydrator services share the same key
- No tagged hydrator key conflicts with a key defined in semantic configuration
- Same validation applies to object mappers

A `DuplicateKeyException` is thrown with a clear error message when a conflict is detected.
